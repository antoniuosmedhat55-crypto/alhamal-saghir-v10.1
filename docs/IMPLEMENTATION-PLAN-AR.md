# خطة تنفيذ متطلبات منصة «الحمل الصغير»

## ما تم فحصه
- التطبيق المنشور يستخدم `server.js` كغلاف يحمّل واجهة HTML مضغوطة من `public/html-chunks`، ويحمّل منطق API مضغوطًا من `bundle-chunks`.
- قاعدة Supabase تحتوي بالفعل جداول `users`, `roles`, `tasks`, `faults`, `attendance`, `leaves`, `purchases`, `locations`, `sections`, `water_logs`, `daily_reports`, `work_events`, `audit_log` وغيرها.
- الأدوار المسجلة حاليًا في جدول `roles`: مدير النظام، مساعد Admin، مدير الصيانة، مشرف الصيانة، فني صيانة. لا توجد أدوار HR أو IT حتى الآن.
- الجداول المنظّمة ليست مصدر البيانات الوحيد للتطبيق الحالي؛ حالة المنصة الأساسية تُحفظ أيضًا في `private.alhamal_state`. لذلك لا يجوز تشغيل migration أو تحويل المصادقة قبل تحديد مسار الترحيل والتحقق من النسخ الاحتياطية.

## خطة التنفيذ المرحلية

### المرحلة 1 — الأمان والصلاحيات ودورة العطل
- توحيد تعريف الأدوار ومصفوفة الصلاحيات في الخادم، وإرجاع 403 للعمليات غير المصرح بها.
- إضافة HR وIT مع الحفاظ على حسابات وأدوار المستخدمين الحالية.
- دورة العطل: جديد ← مسند ← استلمه الفني ← بدأ العمل ← بانتظار الاعتماد ← معتمد/مؤرشف.
- لا تُحذف السجلات؛ تعطيل الحساب يحتفظ بالأعمال وسجل التدقيق.
- إضافة اختبار لكل دور ولكل انتقال حالة.

### المرحلة 2 — الحسابات والحضور والإجازات
- إنشاء/تعديل/تعطيل الحسابات من لوحة الإدارة.
- كلمة المرور المؤقتة تُنشأ خادميًا وتُخزّن كـ hash مملح؛ لا توضع في HTML أو Git.
- فرض تغيير كلمة المرور في أول دخول للحسابات التي تحددها الإدارة.
- توقيت الحضور والانصراف مصدره الخادم، مع إغلاق تلقائي مسجل بوضوح عند 17:00 بتوقيت المنشأة.
- إجازات HR تُعرض وتُعتمد وفق الصلاحيات، والإجازة المعتمدة تستثني الفني من تقييم أيام الإجازة.

### المرحلة 3 — المشتريات والمياه والصيانة الوقائية
- إعادة استخدام جداول المشتريات والمواقع والأقسام والصيانة الدورية.
- دعم نسب متعددة للخزانات والمواقع مع تسجيل منفذ قياس الصباح/المساء.
- الحفاظ على مسار الموافقات وسجل كل تغيير.

### المرحلة 4 — التقارير وIT والتصميم
- تقارير يومية وشهرية، مع توليد ملخص AI عند إغلاق الشهر فقط بعد توفير مفتاح خدمة خادمي.
- لوحة IT تعرض حالة الخدمة والسجلات والأخطاء دون كشف الأسرار أو السماح بتنفيذ SQL عشوائي من الواجهة.
- تحسين RTL والنيون والحركات الخفيفة وواجهة الموبايل مع احترام تقليل الحركة.

## Migration مبدئي
الملف `supabase/migrations/20261027000100_expand_maintenance_rbac.sql` يضيف أدوار HR/IT وحقولًا داعمة لدورة العمل والحضور والمياه. هو **غير مطبق على الإنتاج** عمدًا، ويجب ربطه بكود التطبيق واختباره على نسخة تطوير أولًا.

## معايير القبول قبل النشر
1. `node --check server.js` و`npm run test:security` ناجحان.
2. اختبارات API لكل دور تشمل رفض الوصول غير المصرح به.
3. اختبار دورة العطل كاملة من الإنشاء حتى الاعتماد.
4. اختبار حضور من الخادم والإغلاق التلقائي مع توقيت مصر.
5. اختبار عرض 360px و390px و412px دون تجاوز أفقي.
6. التأكد من أن /api/health يعرض الإصدار الجديد، وأن الإنتاج لم يتغير قبل قبول المعاينة.
7. أخذ نسخة احتياطية والتحقق من إمكانية الاسترجاع قبل أي ترحيل بيانات.
